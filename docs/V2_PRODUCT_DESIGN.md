# DevSupport Agent V2 — 产品与交互设计

> 状态：设计基线
>
> 关联：[V2_SCOPE.md](V2_SCOPE.md)、[V2_TECH_DESIGN.md](V2_TECH_DESIGN.md)。

## 1. 产品承诺

V2 向用户承诺的不是“自动修好故障”，而是：

> 用用户看得懂的语言，交付有证据来源、可复查、能支持人工决策的故障调查结果。

产品应始终优先回答五个问题：

```text
发生了什么？
影响了谁和从何时开始？
Agent 目前确认了什么？
这些判断依据是什么？
我应当由人工下一步做什么？
```

## 2. 使用者与责任边界

V2 只有两类工作角色，不建立产品内账号或角色系统：

| 角色 | 在产品中的工作 |
| --- | --- |
| 团队使用者 | 创建 Incident、阅读调查、补充观察、继续调查、管理团队知识文档。 |
| 部署人员 | 在产品外配置调查目标、数据源地址、只读凭据和服务范围，维护部署与备份。 |

所有访问实例的人默认共享可见性。此假设只适用于可信团队与私有网络。

## 3. 主要用户流程

### 3.1 创建并开始调查

```text
首页
→ 选择调查目标
→ 选择受影响服务
→ 填写发生时间、结束时间和观察到的现象
→ 创建 Incident
→ 启动调查
→ 查看实时调查进度
```

表单只要求用户描述自己实际观察到的现象。它不得要求用户填写根因、修复指令、数据源地址或访问凭据。

### 3.2 阅读调查

调查详情的主视图按以下顺序组织：

1. **当前结论**：调查状态、结论摘要、置信度与未确认事项；
2. **建议下一步**：仅供人工执行的建议、风险和前置条件；
3. **关键证据**：日志、指标、Trace、部署事实和知识 Citation；
4. **调查过程**：用户可理解的时间线，例如“正在收集日志”“发现错误率升高”“假设被支持”；
5. **历史轮次与报告**：每轮调查的快照、差异和原始结论；
6. **技术详情**：原始 Tool 调用、参数、节点、失败分类和预算，默认折叠。

UI 不应让用户把内部 Workflow 节点名当作业务进度，也不应让颜色、前端推断或浏览器状态决定业务规则。

### 3.3 补充并继续调查

终态 Incident 显示入口：`补充信息并继续调查`。

用户填写：

* 新观察到的现象；
* 该现象的发生时间；
* 可选上下文。

系统随后：

```text
保存用户观察
→ 创建下一调查轮次
→ 保留旧假设、Evidence、Tool 历史和报告
→ 基于新旧上下文进行新的只读调查
→ 生成新结论与新报告
```

用户输入是“待验证观察”，不是事实或已执行修复的证明。V2 不提供“确认已恢复”或“标记已修复”按钮。

## 4. 调查目标体验

调查目标是用户所看到的一套可被调查的微服务环境，例如“订单系统测试环境”。

V2 初期只显示部署人员已注册的目标，用户可从中选择；不提供用于填写数据源 URL、Token 或认证信息的自助接入页面。

一个调查目标向用户暴露：

* 中文显示名称与简短描述；
* 可选服务列表；
* 当前可用调查能力，例如“日志、指标”；
* 最近一次连通性状态（若已实现）。

它不向普通用户暴露平台 URL、Secret、Provider 内部查询语法或实现细节。

## 5. 知识库管理体验

可信团队中的使用者可进入 `知识库管理` 页面，完成：

```text
选择调查目标
→ 选择范围：系统共享 / 某个服务
→ 选择环境：通用 / 指定环境
→ 选择文档类型：架构、Runbook、历史事故、配置说明
→ 上传 Markdown
→ 查看解析、索引和启用状态
```

页面必须显示文档标题、所属范围、版本、更新时间、状态和导入失败原因。初期不支持 Word、PDF、图片或 OCR；需要这些格式时，应先转换为 Markdown。

## 6. 中文化原则

* 产品页面、用户错误提示、调查时间线和报告使用中文；
* `Incident`、`Evidence`、`Adapter` 等代码标识、数据库迁移名和 API 字段保持英文；
* 对用户展示的技术词应有清晰中文说明，例如将 `Evidence` 展示为“证据”，将 `INCONCLUSIVE` 展示为“证据不足，暂无法确认”。

## 7. 状态与异常体验

| 情况 | 用户应看到的说明 | 系统行为 |
| --- | --- | --- |
| 正在调查 | 正在收集哪类证据、当前待验证问题 | 持续展示已持久化进度。 |
| 结论成立 | 结论、置信度、关键证据、建议 | 进入 `CONCLUDED` 并保存报告。 |
| 证据不足 | 缺少什么、哪些假设仍无法区分 | 进入 `INCONCLUSIVE` 并保存报告。 |
| 工具或模型失败 | 哪个能力不可用、是否可以稍后继续 | 进入 `FAILED`，不得虚构结论。 |
| 知识上传失败 | 文件或元数据为何不合格 | 不使该文档进入检索库。 |

`CONCLUDED` 不显示为“已解决”；V2 不知道人工是否已经处理故障。
