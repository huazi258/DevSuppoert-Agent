# 微服务故障调查系统概览

## 调查范围

微服务请求通常由一个入口服务协调，并依赖一个或多个下游服务。架构知识只
提供稳定的依赖背景；任何事故结论都必须由当前运行时日志、指标、调用链和
部署事实验证。

## 证据职责

- Logs 用于定位具体请求、错误内容和服务边界。
- Metrics 用于判断错误或延迟是否在一个时间窗内持续、扩大或恢复。
- Traces 用于关联跨服务调用，并确定时间和错误实际出现在哪个 span。

健康检查只能说明进程或端点可以响应，不能证明完整业务路径、下游依赖或
当前配置正确。部署时间与症状相关也不等于部署是因果原因；应分别核对版本
变化、错误模式、调用链和依赖侧信号。

## 调查原则

先限定受影响服务、环境和时间窗，再按照请求标识关联证据。对于错误响应，
至少区分调用方本地失败、下游失败和输入或响应校验失败。对于慢请求，应使用
trace 确认时间消耗的位置；不要仅凭调用方总延迟推断归因或执行处置。
